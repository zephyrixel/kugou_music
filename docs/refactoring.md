# 2026-10 修复与结构收敛记录

本轮保留登录、发现、搜索、音乐库、播放器、推荐电台、会员和日志能力，优先验证 Android。
保留 Riverpod、Drift、手写 SDK 门面和 Lite-only 后端；改动重点是减少重复状态和修复异步边界。

## 问题与落地结果

| 范围 | 原问题 | 当前行为 |
| --- | --- | --- |
| 登录与启动 | 音乐库同步失败阻止进入主界面，资源释放散落在启动分支 | `AppRuntime` 统一管理资源；认证后直接进入主界面，音乐库后台同步并单独重试 |
| 账号切换 | 迟到请求、刷新和回滚可能影响已退出的账号 | `AccountSession` 维护账号代次；在途响应、缓存写入和队列保存检查发起时的身份 |
| SDK 错误 | 只有刷新路径处理认证失效；附带会话保存失败会改写业务成功结果 | SDK 失效统一通知认证层；普通远端写入成功后，安全存储失败只提示并在后续请求重试 |
| 音乐库写入 | 并发修改互相覆盖，旧同步结果可能删除新建歌单 | 同歌单修改顺序执行；同步检查修改版本；回滚恢复原位置与计数，收藏按钮保留用户指定的最终状态 |
| 曲目身份 | 删除可能使用来自另一个歌单的 `fileId` | 只使用目标歌单的曲目标识，缺失时在该歌单内定位 |
| 历史同步 | 收到 100 首旧记录即停止；旧云端记录覆盖较新的本地播放 | 沿游标读取至结束，内存仅保留最新 100 首；时间和累计次数不会回退 |
| 同步状态 | 整数主键被省略，重复插入本应只有一行的状态 | 显式写入 singleton ID，后续同步更新同一行 |
| 分页 | 空页和重复页不停拉取，错误后自动循环，部分重试按钮无效 | 以远端页号推进；空页/无进展页结束；错误后停止自动拉取并支持明确重试 |
| 库内歌单 | 分页器与 Drift 各持有一份歌曲，稀疏缓存误用 offset | 歌曲只从 Drift 读取；控制器仅维护加载状态和游标，部分缓存按远端位置读取 |
| 播放队列 | 切歌提交旧请求快照，覆盖期间追加/排序的歌曲 | 队列控制器唯一持有歌曲与分页状态；同队列切歌按歌曲身份提交，保留并发队列编辑 |
| 试听与清空 | 再次播放可能绕开结束标记；清空未通知已有队列订阅 | 重播与 seek 共用试听范围；清空发布空状态；停止后再释放活动缓存 |
| 队列持久化 | 临时缓存清理会删除队列，枚举依赖声明顺序 | 独立账号记录，v2 字符串枚举，兼容原 v1 数字枚举 |
| 缓存生命周期 | 未使用的音源也永久等待下载完成，同步文件统计阻塞调用线程 | 显式释放准备句柄；只观察实际 HTTP 下载；完成/失败后取消监听，异步统计文件 |
| 底层音频补丁 | 100% 进度早于文件完成落盘，下载失败不通知进度监听 | 完成关闭与重命名后才发布 100%，失败通知观察者并释放资源 |
| 推荐与会员 | 缓冲计入收听时长，基线未就绪就上传画像，初始化与操作交错 | 仅累计 ready 状态的播放；等账号基线和收藏索引完整后上报；会员操作等待初始化并隔离账号代次 |
| 日志 | 全量读取后截断、写入无界、部分凭据形式未脱敏 | 后台有界读取、流式导出、最多 256 条等待写入；Flutter/Rust 写盘前脱敏常见凭据与设备字段 |
| 导航与平台 | 歌单依赖强制非空的动态参数；Android 重复设置刷新率 | 校验有类型的歌单目标并提供错误恢复；仅保留原生刷新率设置，托盘仅随播放状态变化更新 |
| 工程检查 | 只有发布时才测试 | 新增 PR/主分支 Checks，发布复用同一检查流程 |

## 兼容性与生成代码

- Drift schema 从 v8 升为 v9，增加 `stored_playback_queues`，迁移原响应缓存中的账号队列。
  现有登录和音乐库数据保留。退出登录仍清理账号数据。
- `app_database.g.dart` 由 `dart run build_runner build` 生成；未手工修改生成文件。
- Rust 公开 Bridge API 没有变化，不需要更改 FRB 生成绑定。
- SDK、FRB、Freezed 版本保持锁定；移除重复实现对应的 `flutter_displaymode` 依赖。
- `third_party/just_audio` 的局部补丁新增下载完成/失败语义修复，详见其 `KGMUSIC_PATCH.md`。
