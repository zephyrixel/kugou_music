# 安全与隐私

KGMusic 处理登录会话、设备信息和网络播放资源。此文档描述仓库当前的最小安全边界，
不替代平台、服务提供方或组织自身的安全要求。

## 数据处理原则

- Rust SDK 固定使用 Lite 平台配置。
- 登录会话保存在 `flutter_secure_storage`；Rust 导出的会话信封必须是 schema v2，且
  平台为 `lite`。
- 会话与当前设备身份不匹配、格式失效或 schema 过期时会被清除，并要求用户重新登录。
- Drift 仅保存歌曲、歌单、历史、推荐画像和非敏感响应缓存；不得保存 token、Cookie、
  短信验证码、`dfid` 或完整会话。
- 音频缓存以歌曲资源身份和实际音质为键，不把临时签名 URL 当作缓存身份。
- Android 的明文网络默认关闭，仅针对明确的服务域名和回环地址配置例外。

## 数据分类与处置

| 类别 | 示例 | 可存放位置 | 处理要求 |
| --- | --- | --- | --- |
| 高敏感 | token、Cookie、会话 JSON、短信验证码、私钥 | 系统安全存储或 CI secret；用户主动启用 Trace 时可能短暂进入诊断日志 | 普通等级不记录；Trace 日志不得公开提交或分享 |
| 可关联设备 | Android ID、安装 ID、`mid`、`guid`、`uuid`、`dfid` | 设备身份构建/安全存储所需位置；Trace 网络记录可能包含线上的标识符 | 不进入 Drift 或业务缓存；导出日志前复核 |
| 私人业务数据 | 私有歌单、播放历史、用户资料 | Drift 读模型或内存 | 账号隔离；退出时清理账号数据 |
| 非敏感缓存 | 搜索结果、公开歌单、歌词、封面、音频 | Drift 或文件缓存 | 按 TTL/LRU 清理，不把临时 URL 作为资源身份 |
| 运行诊断 | 错误、模块、时间与网络摘要 | 应用日志 | 普通等级最小化；Trace 仅临时排障并在完成后清理 |

## 日志与诊断

Flutter 与 Rust 日志写入应用支持目录，用户可以在应用内查看、导出或清理。日志等级的
数据边界如下：

- `Error`、`Warn`、`Info` 记录错误与生命周期事件，不记录 HTTP 请求/响应头或正文。
- `Debug` 记录方法、脱敏 URL 摘要、状态码、耗时和数据长度；`token`、`signature`、
  `password`、`authorization` 等查询值会被遮盖，但端点、非秘密参数或账号/设备标识仍
  可能出现在摘要中。
- 只有用户在设置页确认启用 `Trace` 后，SDK 才输出完整网络跟踪：完整 URL、请求头、
  响应头（包括 `Set-Cookie`）以及请求/响应正文。单条正文超过 8 KiB 时只保留前缀并标记
  截断。Trace 因此可能包含 token、Cookie、短信验证码、设备标识、用户资料或私人业务
  数据；应用重启后会自动回落到 `Debug`。

Trace 只用于短时间、本机复现。完成排障后应立即切回较低等级并清空日志；导出前必须人工
复核，不能把未脱敏 Trace 日志放进公开 issue、PR、Release、聊天记录或测试 fixture。
私钥、keystore/PFX、密码及其 Base64 编码在任何等级都不得主动写入日志。测试必须使用
合成账号、歌曲和设备数据。

## 密钥管理

正式 Android 和 Windows 签名只通过 GitHub Actions secrets 注入。密钥文件、
`android/key.properties`、PFX/keystore、导出的会话和本地 `.env` 文件不得提交。详情见
[发布指南](releasing.md)。

密钥疑似泄露时，应立即吊销或更换对应签名证书/密码、删除相关 GitHub secret，并审查
已发布构件和 CI 日志，而不是仅删除本地文件。

## 漏洞报告

请不要在公开 issue 中披露可利用的漏洞、有效会话、签名材料或用户数据。对 GitHub
托管仓库，优先使用仓库的私密 Security Advisory 报告；若该入口不可用，请联系仓库
维护者并在公开披露前提供足够的修复时间。

报告应包含受影响版本、复现条件、影响范围、最小复现步骤和建议缓解措施。维护者应在
确认问题后协调修复、回归测试、发布说明和必要的密钥轮换。

## 维护者响应目标

收到私密报告后，先确认是否暴露会话、签名私钥或远程可利用路径；必要时立即撤销 secret 或
证书。修复应包含最小回归测试、受影响版本说明和发布验证。公开说明应描述影响与修复，
但不披露可复用的攻击细节或用户数据。
